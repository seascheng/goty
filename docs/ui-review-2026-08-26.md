# Goty UI 评审 — 2026-08-26

代码级审计,对照已安装的 skills:`apple-hig/distilled`(sidebars/materials/motion)、
`macos-sidebar`(Aguzman)、`apple-design-motion`(WWDC 流体交互 + 阻尼/响应数值)。
截图评审待支持图像的模型补做(`/tmp/goty-review-1.png` 已存,窗口 1280×800)。

## 结论

好的部分不动:系统字体、13pt 行标签、单一圆角值(6)、侧栏两级层级、
View 菜单 Toggle Sidebar ✓、行复用纪律、设置窗分组表单结构。

问题按 blocking → polish:

### 1. BLOCKING — 全应用零动效,所有状态切换是硬切

`Sources/UI/` 内没有任何 `NSAnimationContext`/`CASpringAnimation`(所有动画命中
都在 vendored ghostty 里)。具体硬切点:

| 位置 | 现状 |
|---|---|
| `AppWindowController.toggleSidebar()` | 宽度 constant 直接改,无动画 |
| `Sidebar.setCollapsed()` | `isHidden` 翻转 |
| `PaneHost.hideAITask()` (TerminalViews.swift:557) | `removeFromSuperview()` 硬消失 |
| `RightPanel.setCollapsed()` | 宽度跳变 |

rubric:apple-design-motion §3(可打断)、§4(默认阻尼 1.0 / 响应 0.3–0.4)、
§7(进出同路径对称)、§12(materialize,不是 pop)。
这是"UI 不满意"的最大单一来源 — 和 Warp/Ghostty 比手感差距就在这。

修法:统一一个 `Chrome.animate(_ duration: 0.3)` 包装(NSAnimationContext,
spring 计时),侧栏宽度/卡片进出/面板折叠全部走它;卡片进场 = 底部 anchored
位移+淡入(同路径出场),不是纯 alpha。

### 2. BLOCKING — 侧栏最小宽 180pt,低于规范下限

`AppWindowController.setSidebarWidth` clamp 是 `180...460`。
rubric:macos-sidebar — 最小 225–275pt(更窄行标签截断、选择 pill 挤压)。
修法:下限改 225,一行。460 上限超 350–400 建议,可保留(终端长主机名场景)
但标 `ponytail:` 注释说明理由。

### 3. HIGH — 无 reduced-motion 适配

`Sources/` 内零处 `accessibilityDisplayShouldReduceMotion`。做了 #1 之后必须
跟上:reduce motion 时位移动画降级为 cross-fade(apple-design-motion §14)。

### 4. HIGH — 不用系统材质/振动色,文本不随系统外观自适应

`Sources/` 无 `NSVisualEffectView`;文本色全部取自 `Chrome.theme` 固定色。
rubric:materials.md — 侧栏属标准材质层,文字用 vibrant 系统色
(`.labelColor`/`.secondaryLabelColor`)自动适配深浅色/无障碍。
最小修法(不动 ghostty 主题跟随设计):文本色改 vibrant 系统色;
材质(半透明侧栏)可选、放设置项。终端内容区保持不透明 ✓(内容层不用
玻璃,HIG 明文)。

### 5. MEDIUM — 侧栏截断标签无 expansion tooltip

Aguzman:截断标签 hover 应展开全文。修法一行/字段:
`(labelField.cell as? NSTextFieldCell)?.allowsExpansionToolTips = true`。

### 6. LOW — 图标用 lucide 而非 SF Symbols

HIG 偏好 SF Symbols;tty7 参照与终端审美选 lucide 是有意为之 — 保留,仅记录。

## 建议实施顺序

1(#1+#2+#3 一次做完,同一族) → 4(最小版:仅 vibrant 文本色) → 5。
